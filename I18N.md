# Languages on WhichPadel

Every page of every language is rendered by **one shared view per page type**. There are no per-language page files, copies or cut-down versions. Only strings differ, and they live in `src/i18n/`.

## How it fits together

| Piece | File |
|---|---|
| Route map (URL of every page type in every language) | `src/i18n/routes.js` (`P`, `LANGS`, `LOCALE`, `BEST_SLUG`) |
| Page generator (all languages, all types) | `src/pages/[...path].astro` (+ `src/pages/404.astro` for the root 404) |
| One view per page type | `src/views/V*.astro` (home → `components/Home.astro`) |
| Shared layout, nav, footer, region picker | `src/layouts/Base.astro`, `components/NavL.astro`, `FooterL.astro`, `Region.astro` |
| UI strings, terms, page copy | `src/i18n/<lang>.js` (`en.js`, `es.js`, `fr.js`) |
| Homepage strings | `src/i18n/home.js` (one block per language) |
| Buying-guide prose | `src/i18n/guide-<lang>.js` |

Page types: home, guide, compare, bestIndex, best, racket, brands, brand, brand2027, players, player, vs, tool, bf, privacy, affiliate, about, 404.

## Adding a language (example: Portuguese, `pt`)

1. **Dictionary.** Copy `src/i18n/es.js` to `src/i18n/pt.js` and translate every value. Set `lang:'pt'`, `locale:'pt-PT'`, `region:'PT'`, `name:'Português'`, `short:'PT'`. The build fails (`checkDicts()` in `src/i18n/index.js`) if any key is missing, extra or of the wrong kind.
2. **Homepage strings.** Add a `pt:{...}` block to `src/i18n/home.js` with the same keys as `en`.
3. **Guide prose.** Copy `src/i18n/guide-es.js` to `guide-pt.js` and translate. Register it in `src/views/VGuide.astro` (`{en:gEN,es:gES,fr:gFR,pt:gPT}`).
4. **Register the dictionary** in `src/i18n/index.js` (`import pt from './pt.js'`, add to `DICTS`).
5. **Routes.** In `src/i18n/routes.js`: add `'pt'` to `ALL_LANGS` and the default `LANGS`, add `pt:'pt-PT'` to `LOCALE`, add a `pt:` slug to every `BEST_SLUG` entry, and a `pt:` path builder to every entry in `P` (e.g. `home:{...,pt:()=>'/pt/'}`).
6. **Language names** for the switcher: add `pt:'Português'` to `LN` in `Base.astro`, `NavL.astro`, `FooterL.astro`; add the `og:locale` mapping in `Base.astro`.
7. Run `./deploy.sh`. hreflang, sitemap and canonical tags are generated from the route map automatically; `seoqa.mjs` and `parity.mjs` must pass.

Nothing else should be needed. If a step above needs a code change in a view, that is a bug: move the string into the dictionary instead.

## Rules

- Never add an `if (lang === ...)` branch for wording or layout. Formatting that differs by language (e.g. "Round shape" vs "Forma redonda") is a dictionary function (`terms.fShape`, `fBal`, `fCore`, `home.js` `balF`...).
- Strings passed to client scripts via `define:vars` must be plain data. Turn template functions into `'§'` placeholder strings first (see `VCompare.astro`, `VTool.astro`, `Home.astro`).
- The only language-specific content allowed is the English-only data credit on About (`legal.credit`, marked `data-parity-skip`).

## Checks (run by `./deploy.sh` via `qa.mjs`)

- `parity.mjs` loads a sample of every page type in en/es/fr at 390px and 1280px and fails if the DOM skeleton (tags and classes) or computed spacing differs between languages.
- `seoqa.mjs` checks canonical tags, and that hreflang (en/es/fr + x-default) is complete and reciprocal, on every built page.
- `mixqa.mjs` flags wrong-language words on es/fr pages.
